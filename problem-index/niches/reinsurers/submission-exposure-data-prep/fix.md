# The Same File Cleaned by Twelve Reinsurers

**Niche:** [[niches/reinsurers/submission-exposure-data-prep/profile|Submission & Exposure Data Preparation]]
**Industry:** [[industries/reinsurers|Reinsurers]]
**Type:** Fix (Pain Point)
**One-liner:** A programme with twelve reinsurers on its panel has its exposure cleaned twelve times, slightly differently each time, and the cedent never learns what any of them fixed.
**Tags:** #large-language-models #feature-engineering #data-integration #automation #workflow-orchestration #worker-facing
**Contested on:** Every serious competitor in this niche is fighting to turn a cedent's exposure submission into a model-ready file with a data-quality score within hours of arrival, and whoever's cleaned files need the fewest manual fixes in December takes the account.

## The Problem
Each panel reinsurer receives the same broker file and repeats the same corrections. The fixes never flow back to the cedent, so next year's file has the same defects.

## Why It's Still Broken
Each reinsurer treats its cleaned file and its view of the data as part of its competitive edge, and brokers have no mechanism to collect corrections.

## What a Fix Looks Like
A cedent-facing defect report generated from the reinsurer's cleaning, sent through the broker. It names the specific fixes that would most reduce modelled uncertainty, so the next submission arrives cleaner without sharing the reinsurer's pricing view.

## Who Feels the Pain
Exposure analysts repeating corrections each December; cedents paying data-quality loads they cannot see; brokers fielding the same queries from every panel member.

## Impact If Fixed
Cleaner submissions year on year, and fewer December hours lost to fixing the same defects.
