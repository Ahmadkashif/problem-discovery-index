# Site Yield Tools With Local Code and Zoning Logic

**Niche:** [[niches/architecture-firms/multifamily-mixed-use-housing/profile|Multifamily & Mixed-Use Housing]]
**Industry:** [[industries/architecture-firms|Architecture Firms]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Yield tools apply setbacks and height limits; the local density bonus, the parking reduction near transit and the construction-type height limit are typed in by hand.
**Tags:** #large-language-models #feature-engineering #compliance #automation #data-integration
**Contested on:** Every serious competitor in this niche is fighting to fit the most rentable units onto a site under zoning and code at a construction cost per unit that makes the developer's pro forma pencil, and whoever proves yield and cost fastest at feasibility takes the account.

## The Problem
The first hours of every feasibility study go to reading the zoning code: base density, height, floor-area ratio, setbacks and step-backs, open space, parking minimums or maximums, and the bonuses that change everything — state density bonus programmes, affordable housing incentives, transit-oriented reductions. Then the building code constrains height and area by construction type. Each is entered into the yield tool manually.

## What Already Exists
TestFit, Autodesk Forma and similar generative site tools; zoning data services that digitise parcel zoning; UpCodes and ICC Digital Codes for building code.

## The Customization Gap
The adaptation needs: zoning parameters including bonus programmes loaded per parcel from local ordinances, with the source clause cited; building-code height, area and construction-type limits applied automatically; options that show which bonus or code path each scheme relies on; and change alerts when a city amends its ordinance mid-pursuit.

## Target Customer
Feasibility and housing teams at architecture firms already licensing a yield tool.

## Impact If Solved
Hours saved per study and fewer schemes that collapse when the zoning reading is checked properly.
