# Assessing a Business Through a Screenshot

**Niche:** [[niches/ecommerce-aggregators/the-diligence-analyst/profile|The Diligence Analyst]]
**Industry:** [[industries/ecommerce-aggregators|Ecommerce Aggregators]]
**Type:** Build (Greenfield Opportunity)
**One-liner:** A diligence analyst evaluates an acquisition target through screenshots and exports from a marketplace reporting interface built for sellers, under a deadline set by a competitive auction.
**Tags:** #worker-facing #evaluation-metrics #automation #data-integration #confidence-intervals #descriptive-statistics #revenue-impact #time-series-forecasting
**Contested on:** Every serious competitor in this niche is fighting to give an analyst a real view of a target instead of seller-interface screenshots under an auction clock — and whoever does that takes the deal quality, because the analyst's output is the only thing standing between capital and a bad acquisition.

## The Problem
An analyst is given seven days, a folder of screenshots, two spreadsheets the seller prepared, and a ninety-minute screen share. From that they must establish whether the revenue is durable. They cannot see the ranking history, the review acquisition pattern, the advertising dependence over time, the return rate by product, or what happened to the category's competitive structure in the last year. They reconstruct what they can, write a memo listing five things they could not verify, and the committee approves because the price is competitive and the unverified items are the same ones on every deal.

## Why Nobody Has Built This
The marketplace's seller interface is the only source and it was built for a different purpose. The seller controls the data and has no reason to volunteer what would reduce the price. External reconstruction of ranking and review history is possible and nobody built the tooling. And the unverified items are the same on every deal, which normalises them rather than making them a blocker.

## What to Build
Reconstruct the view the interface does not provide. Build ranking, review and price history externally from public marketplace data, which is collectable continuously and independently of the seller and is the single largest addition to what an analyst can see — the history the interface will not show can be built by anyone willing to collect it in advance. Standardise the data request so every deal produces the same exports in the same form, which makes analysis repeatable and comparison across deals possible. Verify seller figures against independent evidence where it exists, since several key numbers can be cross-checked and currently are not. Assess the category systematically — entry rate, price trend, concentration, review inflation — from the same external data, which is the context that determines durability and is currently a judgement. Template the analysis by category, so an analyst is not designing the work each time. Produce a persistence assessment rather than a financial summary, which is the underwriting output and is what the committee should be deciding on. Track which diligence findings predicted outcomes, so the template improves across deals. And say plainly what could not be verified and what it would take, because the current practice normalises the gaps rather than pricing them.

## Target Customer
Acquisition teams and investment committees, the analysts, and the capital behind the deals.

## Impact If Built
The seller interface was built to help a seller run a business, not to help a buyer assess one, and the missing history is externally collectable in advance. A persistence assessment rather than a financial summary is the output the committee should be deciding on.
