# Incrementality Operations

**Parent Industry:** [[industries/game-user-acquisition-firms|Game User Acquisition Firms]]
**Category:** ⚡ Highly Automatable
**Contested on:** Every serious competitor in this niche is fighting to run incrementality tests often enough to know what their spend is actually buying, when each one is currently a project — and whoever makes them routine takes the account.

## Profile
**Market Size:** ~$1.2B US
**Share of Parent Industry:** ~3% of category spend
**Digital Adoption:** Medium — occasional
**Target Buyer:** UA measurement
**Automation Potential:** Very high — test design, execution and readout

## What Makes This a Distinct Niche
Incrementality testing is the only way to know whether acquisition spend caused anything, and it is run occasionally because each test is treated as a project: design it, negotiate the holdout, wait, analyse, present. The consequence is that most spend decisions are made on attributed rather than incremental numbers, and the tests that would correct them happen once or twice a year. Making them routine is an operations problem rather than a methodological one.

## Current Tools & Gaps
A geo test someone designed, a network's own lift study of uncertain independence, and an attribution platform. The gaps: no standing test infrastructure; no automated design and power calculation; no continuous holdouts; no standard readout; and no accumulation of results across tests.
