# The Best Event We Ever Ran

**Niche:** [[niches/game-liveops-services/event-evaluation/profile|Event Evaluation]]
**Industry:** [[industries/game-liveops-services|Game LiveOps Services]]
**Type:** Fix (Pain Point)
**One-liner:** The event broke every revenue record, is cited in every planning meeting since, and the cohort that played it churned faster than any other.
**Tags:** #quick-win #survival-analysis #evaluation-metrics #descriptive-statistics #causal-inference #confidence-intervals #revenue-impact #change-point-detection
**Contested on:** Every serious competitor in this niche is fighting to measure what an event cost over the following months rather than what it earned in the week it ran — and whoever measures the cost takes the account.

## The Problem
Every live team has one: the record-breaking event that became the template. It ran hard, earned enormously, and is now the reference point for what a good event looks like. Nobody has checked what happened to the players who participated most heavily over the following six months. Where anyone has looked, the answer is frequently that they churned at an elevated rate — and the template has been repeated a dozen times since.

## Why It's Still Broken
Nobody looked back — an event evaluated once, in its own week, and then cited forever is never re-examined, because there is no moment in any process at which someone is asked to. The cohort data exists and the query is never run. The event's reputation is organisationally useful. And revisiting it would implicate the calendar that followed.

## What a Fix Looks Like
Run the retrospective query on the events you already ran. Pull retention curves for heavy participants in past events against matched non-participants, which is the fix and is a query against data already held. Compare the event's cohorts six months out rather than one week out, since that is where the effect lives. Do it for the whole back catalogue of events at once, as the pattern across a dozen events is far more convincing than any single case. Rank past events by net effect rather than by gross revenue, which frequently reorders the list completely. Acknowledge the self-selection in the comparison and adjust for it, because heavy participants differ and an unadjusted result will be dismissed. Look specifically at the mid-tier spenders, as the top tier is usually resilient and the middle is where the damage lands. Identify which design features correlate with the worst outcomes. Circulate the result before the next calendar is planned, which is the moment it can change anything. Present it as a measurement rather than as a criticism of the team that ran it. And add the six-month readout to the standard event report so it happens automatically thereafter.

## Who Feels the Pain
Live teams repeating a template that costs more than it earns; players worn out by a design copied a dozen times; analysts who suspected it; and a game whose decline nobody can attribute.

## Impact If Fixed
An event evaluated once, in its own week, and then cited forever is never re-examined, because no process asks anyone to. Pulling six-month retention curves for past events reorders the ranking on data already held.
