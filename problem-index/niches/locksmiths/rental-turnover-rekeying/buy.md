# Property-Management Work Orders Extended to Access Records

**Niche:** [[niches/locksmiths/rental-turnover-rekeying/profile|Rental-Turnover Rekeying & Smart-Lock Retrofit]]
**Industry:** [[industries/locksmiths|Locksmiths]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Property-management software already opens a "rekey" work order at every move-out; it records that a vendor was paid, not which cylinder, core or code now controls the door.
**Tags:** #data-integration #workflow-orchestration #compliance #automation #descriptive-statistics
**Contested on:** Every serious competitor in this niche is fighting to reset access at every unit turn before the next resident moves in, and whoever can prove every door was reset before move-in, by rekey or smart-lock code change, at the lowest cost per turn takes the account.

## The Problem
The move-out triggers a turn checklist that includes "rekey locks". The locksmith completes it and invoices. The manager cannot later show which key combination or code was in place for which resident, or prove that access was reset. That matters in a break-in dispute or a security complaint.

## What Already Exists
Yardi, AppFolio and RealPage handle turn checklists, vendor work orders and payments. Smart-lock platforms keep their own credential logs, and some integrate with property-management software for move-in and move-out events.

## The Customization Gap
The extension gives each unit an access record that holds door hardware, keyway and core or pinning reference (not the bitting itself in plain view), the smart-lock device and credential events, and the date access was last reset with the vendor's confirmation. Move-out should trigger the reset automatically: a code change on smart units, a rekey order with the unit's hardware details on mechanical ones. Proof of completion would be required before the move-in date is released.

## Target Customer
Property managers running mixed mechanical and smart-lock portfolios, and their locksmith vendors.

## Impact If Solved
Access resets become provable and on time, inside the system that already runs the turn.
