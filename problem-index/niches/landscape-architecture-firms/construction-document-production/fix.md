# Detail Libraries Copied From Project to Project

**Niche:** [[niches/landscape-architecture-firms/construction-document-production/profile|Construction Document Production & Quantity Takeoff]]
**Industry:** [[industries/landscape-architecture-firms|Landscape Architecture Firms]]
**Type:** Fix (Pain Point)
**One-liner:** The office's standard details are whatever the last project used, so discontinued products, outdated dimensions and old mistakes reappear in every set.
**Tags:** #large-language-models #transformers #k-nearest-neighbors #quick-win #automation
**Contested on:** Every serious competitor in this niche is fighting to keep the plan, plant schedule, details, specifications and estimate in sync through every revision so the bid set goes out without coordination conflicts, and whoever eliminates the manual coordination pass takes the account.

## The Problem
Paving sections, edge restraints, tree planting details, wall sections and furnishing installation details are copied from the most recent project rather than from a maintained library. A detail corrected after an RFI on one job is not corrected in the next; a manufacturer renames a product and the old name lives on for years.

## Why It's Still Broken
Maintaining a detail library is overhead nobody bills; corrections made in construction are not written back; and there is no record of which details generated RFIs.

## What a Fix Looks Like
A maintained office library with version history, links from each detail to the RFIs and field issues it generated, manufacturer product checks against current catalogues, and a warning when a project uses a superseded version.

## Who Feels the Pain
Production staff, construction administrators answering the same RFI on successive projects, and contractors pricing ambiguous details.

## Impact If Fixed
Recurring detail RFIs eliminated and the office's construction lessons kept in the library rather than in someone's memory.
