# Build & Toolchain Management

**Parent Industry:** [[industries/game-porting-studios|Game Porting Studios]]
**Category:** ⚡ Highly Automatable
**Contested on:** Every serious competitor in this niche is fighting to keep several platforms' builds working across every project, every SDK update and every client engine version — and whoever makes that reliable takes the account.

## Profile
**Market Size:** ~$50M US
**Share of Parent Industry:** ~3% of category revenue
**Digital Adoption:** Medium — bespoke
**Target Buyer:** Build engineering
**Automation Potential:** Very high — pipeline standardisation

## What Makes This a Distinct Niche
Every project needs builds for several platforms, on several configurations, against SDK versions that update on the platform holders' schedules, for a client engine that may be heavily modified. The pipeline is rebuilt per project, breaks constantly, and blocks engineers when it does. It is the least glamorous and most repeated engineering in the business, it is almost entirely mechanical, and each project's solution is thrown away at the end.

## Current Tools & Gaps
A build script inherited from the last project, a devkit in a cupboard and a build machine somebody maintains. The gaps: no reusable pipeline across projects; no SDK version management; no build reproducibility; no automatic recovery when a build breaks; and no capacity planning for build and devkit resources.
