# The Monthly Report Assembled by Hand

**Niche:** [[niches/audio-adtech-networks/the-ad-operations-specialist/profile|The Ad Operations Specialist]]
**Industry:** [[industries/audio-adtech-networks|Audio Adtech Networks]]
**Type:** Fix (Pain Point)
**One-liner:** Every client report is built by exporting from two systems, pasting into a template and reconciling the differences by judgement, every month, for every client.
**Tags:** #automation #workflow-orchestration #data-integration #descriptive-statistics #quick-win #evaluation-metrics #worker-facing #compliance
**Contested on:** Every serious competitor in this niche is fighting to let one person run two incompatible businesses and report them as one — and whoever does that removes the reconciliation that consumes the category's operational capacity.

## The Problem
Month end. Export dynamic delivery from the ad server. Pull host-read delivery from the spreadsheet, cross-referencing which episodes published and which reads were confirmed. Reconcile the two definitions of an impression. Add promotional code redemptions from the client's own report, which arrives late. Paste into the client's template. Write a paragraph. Repeat for every client. The specialist spends a week of every month on this, the numbers are correct, and nothing about the exercise required judgement except the reconciliation — which is the same reconciliation every month with the same causes.

## Why It's Still Broken
Reporting is treated as an output to produce rather than as a process to automate, and the manual version works, which removes the pressure — a week that is always available is a week nobody counts. Each client's template differs, which makes automation feel bespoke. The reconciliation requires knowledge held by the specialist. And nobody has measured the time.

## What a Fix Looks Like
Automate the assembly. Generate the report from both systems against a shared delivery model, which is the fix and follows directly from the build note's object model — the merge is only manual because the two systems have no shared concept. Templatise client formats rather than treating each as unique, since the differences are cosmetic and the content is identical. Encode the reconciliation rules explicitly, so the specialist's knowledge is applied by the system and survives them. Pull promotional code data automatically where the client permits, which removes the late dependency that delays everything. Produce the report continuously so it is available on demand rather than at month end, which changes the client relationship as well as the workload. Flag exceptions for the specialist rather than requiring them to build everything. Keep the narrative light and generated, since most months are unremarkable and the commentary is largely ritual. Reconcile against invoicing in the same pass, which catches billing errors before the client does. Measure the time recovered, because that is the case for building it. And give the specialist the freed week for the work that actually needs them — campaign quality, client relationships and the delivery risks that currently surface too late.

## Who Feels the Pain
Specialists losing a week a month to assembly; clients receiving reports late because the process is manual; and networks whose operational capacity caps how many clients they can serve.

## Impact If Fixed
A week that is always available is a week nobody counts, and the merge is manual only because the two systems share no delivery concept. Generating from a shared model with encoded reconciliation rules returns the week and makes the specialist's knowledge outlast them.
