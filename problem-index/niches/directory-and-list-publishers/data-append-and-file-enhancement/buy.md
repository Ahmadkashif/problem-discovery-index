# Identity Resolution Platforms Pointed at an Append Job

**Niche:** [[niches/directory-and-list-publishers/data-append-and-file-enhancement/profile|Data Append & File Enhancement]]
**Industry:** [[industries/directory-and-list-publishers|Directory & List Publishers]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Identity resolution platforms link a client's records to each other; an append job links them to a compiler's file and must account for every field returned.
**Tags:** #k-nearest-neighbors #word-embeddings #evaluation-metrics #data-integration #compliance
**Contested on:** Every serious competitor in this niche is fighting to append the most correct fields to a client's file — a match rate at a stated accuracy — and whoever proves the higher verified match rate on the client's own test file wins the job.

## The Problem
A compiler running append jobs needs consistent matching across clients, defensible accuracy and licence control over what it returns.

## What Already Exists
Identity resolution and entity matching platforms (LiveRamp, Senzing, AWS Entity Resolution) with configurable rules and probabilistic matching.

## The Customization Gap
An append workflow needs: person-to-company matching for B2B files (a contact at a firm that has since been acquired); household versus individual rules for consumer files; confidence per appended field, not per record; licence terms stamped on every value (permitted channel, term); suppression of deleted and opted-out people before return; and a client test-file protocol that reports matched-and-correct on a sample the client can verify.

## Target Customer
Data operations leads at compilers and service bureaus.

## Impact If Solved
Append becomes a measured, licence-controlled service rather than a black-box match rate.
