# Pipeline Discipline From Software Delivery

**Niche:** [[niches/conversion-optimization-firms/experiment-operations/profile|Experiment Operations]]
**Industry:** [[industries/conversion-optimization-firms|Conversion Optimization Firms]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Software made the path to production automated and gated, and experiments are launched from a checklist.
**Tags:** #automation #workflow-orchestration #compliance #evaluation-metrics #data-integration #change-point-detection #descriptive-statistics #quick-win
**Contested on:** Every serious competitor in this niche is fighting to run a continuous programme of tests without the setup, quality assurance and monitoring consuming the capacity, and whoever automates that takes the account.

## The Problem
Software delivery made the path from a change to production automated and gated: checks run without anyone remembering, quality gates block rather than warn, deployment is a command, and monitoring after release is continuous. The effect was to make frequent releases safe and to remove a class of human error entirely. Experiment operations is a comparable path with comparable failure modes and runs on a document listing what somebody should remember to do.

## What Already Exists
Automated gates that block rather than warn; checks that run without being invoked; one-command deployment; post-release monitoring; and a record of what was released and when.

## The Customization Gap
The adaptation is to a release whose correctness is statistical as well as technical. It requires: (1) gates that are statistical — power, sample ratio, stopping rule — as well as technical, which no delivery pipeline has any notion of and which is the substantive difference; (2) a release that runs for weeks and must be monitored throughout rather than checked at deployment; (3) variants deployed into a client's site rather than the team's own application; (4) a conclusion step with a decision rule, which has no delivery analogue; and (5) operators who are strategists rather than engineers.

## Target Customer
Conversion optimisation firms and experimentation teams, testing platform vendors, programme operations, and delivery tooling providers.

## Impact If Solved
Software made the path to production automated and gated, removing a class of human error. Statistical gates alongside the technical ones, over a release that runs for weeks, is what the experiment version must add.
