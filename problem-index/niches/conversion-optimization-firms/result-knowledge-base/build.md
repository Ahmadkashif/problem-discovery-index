# A Record of What Was Established

**Niche:** [[niches/conversion-optimization-firms/result-knowledge-base/profile|Result Reporting & Knowledge Base]]
**Industry:** [[industries/conversion-optimization-firms|Conversion Optimization Firms]]
**Type:** Build (Greenfield Opportunity)
**One-liner:** Fifty tests a year and the accumulated knowledge is a folder of slides.
**Tags:** #data-integration #evaluation-metrics #automation #descriptive-statistics #workflow-orchestration #word-embeddings #confidence-intervals #bayesian-inference
**Contested on:** Every serious competitor in this niche is fighting to keep what its tests established in a form anyone can retrieve, and whoever builds that record takes the account.

## The Problem
A long-running programme's value should compound: each test narrows what is worth trying next and each effect size informs the next estimate. Instead each test produces a slide and the knowledge evaporates. New strategists propose tests that have been run. Effect size estimates are guessed rather than drawn from the programme's own history. The same page is tested repeatedly with no memory of what was already established about it.

## Why Nobody Has Built This
The deliverable is a monthly report rather than a record, so nothing structured is produced. Platforms store results without the hypothesis or the context that makes them interpretable. Nobody owns the archive. And a folder of decks looks like a record until somebody tries to use it.

## What to Build
Record the test as a structured entry and generate the report from it. Capture each test as a structured record — hypothesis, mechanism, page, change, design, result with interval, decision — which is the core and is what makes a programme's history usable. Generate the monthly report from those records rather than assembling it, which removes the recurring cost and produces the record as a by-product. Make the archive retrievable by page, hypothesis type and mechanism rather than by date. Detect when a proposed test resembles one already run, which is the retrieval that saves the most. Accumulate effect sizes by change type to inform future power calculations, which is the input nobody has and everybody needs. Record null results in the same form as wins, since a programme that only remembers wins learns the wrong lesson. Carry implementation status, so it is known whether a winner ever shipped. Keep it across client engagements at the pattern level, which is the agency's accumulating asset. Report the programme's own effect size distribution, which is more informative about what to expect than any industry benchmark. And make recording the result the way a test is concluded rather than an additional step.

## Target Customer
Conversion optimisation firms and in-house experimentation teams, testing platform vendors, programme operations, and knowledge management providers.

## Impact If Built
A programme's value should compound and instead each test produces a slide. A structured record that generates the report makes the history retrievable and supplies the effect size priors nobody has.
