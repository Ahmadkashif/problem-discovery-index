# Code Corpus Intelligence

**Parent Industry:** [[industries/developer-tools-vendors|Developer Tools Vendors]]
**Category:** Highly Automatable
**Contested on:** Every serious competitor that gets here is fighting to turn the record of how software is actually written across millions of repositories into a product — and whoever does it holds the only dataset from which the category's central question could be answered.

## Profile
**Market Size:** ~$560M US, largely latent
**Share of Parent Industry:** ~4% of category revenue
**Digital Adoption:** None — the corpus is used to render diffs
**Target Buyer:** The platform vendors themselves; secondarily engineering leadership
**Automation Potential:** Very High — the corpus is complete, structured and already stored

## What Makes This a Distinct Niche
These vendors hold the most detailed record in existence of how software is written: what gets edited and how often, which code is revisited repeatedly, where reviews stall and why, which changes precede incidents, how long a piece of code survives before being rewritten, and how all of that shifts when a tool or practice is introduced. That corpus is the only place the industry's central and increasingly expensive question — does this make engineering better — could be answered empirically rather than by assertion. It is also the source of answers to questions nobody currently asks: which code in a repository is a maintenance liability by its revision history rather than by any static metric, which review practices actually catch defects, which dependencies predict incidents. The category renders diffs and stores blobs, and the corpus sits unexamined.

## Current Tools & Gaps
Repository insights of a descriptive kind, contribution graphs, and engineering analytics vendors working from the same data at a single customer's scale. The gaps: nothing analyses across customers, so every finding is a single organisation's anecdote; the revision history is treated as an audit trail rather than as a signal about code quality; the relationship between practice and outcome is unmeasured, so engineering norms remain matters of opinion; and no vendor has articulated a governance position for corpus analysis, so the topic is avoided rather than designed.
