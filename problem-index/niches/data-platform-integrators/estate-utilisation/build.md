# Which of What We Built Earns Its Keep

**Niche:** [[niches/data-platform-integrators/estate-utilisation/profile|Estate Utilisation]]
**Industry:** [[industries/data-platform-integrators|Data Platform Integrators]]
**Type:** Build (Greenfield Opportunity)
**One-liner:** The firms that build measurement systems for everyone else have never measured their own output.
**Tags:** #data-integration #evaluation-metrics #descriptive-statistics #graph-theory #revenue-impact #confidence-intervals #automation #optimization-fundamentals
**Contested on:** Every serious competitor in this niche is fighting to establish which of the models and dashboards it has built are actually used, when the query log holds the answer and nobody has ever run it — and whoever answers it takes the account.

## The Problem
An integrator's deliverable is a platform, a model layer and a reporting layer, and the measure of success is whether people get answers from it. That measure is not taken. Query logs record every access to every asset, lineage records what depends on what, and cost attribution records what each model costs to run. Joining those three answers the discipline's governing question — which of what we built earns its keep — and no firm produces the report, partly because the answer would be uncomfortable.

## Why Nobody Has Built This
The data belongs to the client and the engagement ends at delivery. The answer would show assets billed for and never opened, which is awkward for a business priced by delivery volume. Nobody has been asked. And the estate's size is treated as evidence of value.

## What to Build
Join the three logs and report what the estate actually is. Join the delivery record to the query log and the cost attribution, which is the core and is the report the whole discipline is missing. Classify the estate into working assets, occasional assets and inventory, since the distinction governs every subsequent decision. Report usage by consumer as well as by asset, as an asset used by one person weekly is a different thing from one used by fifty. Attribute cost per asset against its use, which turns an abstract rationalisation argument into a number. Measure across engagements to establish what proportion of delivered work is typically used, which is the finding that changes how much gets built. Include dashboards and downstream consumers, not only models. Report at delivery and again at ninety days, so the decay is visible. Offer it as a paid service to clients with mature estates, which is a straightforward sale to anyone who suspects their estate is mostly inventory. Feed the finding back into delivery scoping, which is where the firm's own practice improves. And publish the aggregate proportion without client specifics, which would be the most commercially useful statement any integrator could make.

## Target Customer
Data platform integrators and analytics consultancies, client data leadership, platform vendors, and data governance and observability providers.

## Impact If Built
Query logs, lineage and cost attribution all exist and nobody joins them, which is the one report that would settle what the estate is. Classifying the estate into working assets and inventory turns an argument into a number.
