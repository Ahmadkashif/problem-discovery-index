# Healthcare Interface Engines for Spot Orders

**Niche:** [[niches/media-rep-firms/avails-to-order-workflow/profile|Avails, Proposals & Order Exchange]]
**Industry:** [[industries/media-rep-firms|Media Representative Firms]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Hospitals connect dozens of systems from competing vendors through interface engines that map messages between schemas; spot TV has the same many-to-many problem and no neutral engine.
**Tags:** #data-integration #workflow-orchestration #automation #evaluation-metrics #quick-win
**Contested on:** Every serious competitor in this niche is fighting to move an avail request, proposal, order and every revision between the agency's buying system and each station's traffic system without anyone re-keying it, and whoever closes the re-keying gap for the most agency–station pairs becomes the default pipe for spot.

## The Problem
Each agency system and each traffic system speaks its own dialect, and bilateral integrations cover only some pairs.

## What Already Exists
Healthcare interface engines such as Rhapsody and InterSystems HealthShare receive messages in one system's format, transform them to another's, route them and keep a full message audit, connecting many vendors' systems through one hub.

## The Customization Gap
The adaptation needs message types for avails, proposals, orders, revisions, makegoods, invoices and affidavits, mapped to the TVB electronic transaction standards where they apply. It needs connectors to Mediaocean, Strata, WideOrbit, Imagine and RCS, and station-specific mapping of dayparts and inventory codes. Message-level reconciliation must show where an order diverged.

## Target Customer
Rep firm and station group sales operations; possibly a neutral industry utility funded by both sides.

## Impact If Solved
One hub replaces many bilateral integrations, and every transaction has an audit trail.
