# Lineage as a Support Tool

**Niche:** [[niches/financial-data-vendors/the-client-data-specialist/profile|The Client Data Specialist]]
**Industry:** [[industries/financial-data-vendors|Financial Data Vendors]]
**Type:** Build (Greenfield Opportunity)
**One-liner:** The specialist reconstructs each number's derivation from audit logs and memory because nothing assembles it for them.
**Tags:** #large-language-models #word-embeddings #data-integration #evaluation-metrics #worker-facing #workflow-orchestration
**Contested on:** Every serious competitor in this niche is fighting to answer "why does your number differ" faster and more convincingly than the competing terminal — and whoever can show the derivation wins the argument that decides which vendor the client trusts at renewal.

## The Problem
Discrepancy tickets require source, components, adjustments, policy and restatement history, scattered across systems.

## Why Nobody Has Built This
Lineage was never captured as a product; support was never an engineering priority.

## What to Build
A lineage view per value, a reconciliation against the issuer's own figure, and a drafted, cited explanation the specialist reviews.

## Target Customer
Client service leadership at terminal and fundamentals vendors.

## Impact If Built
Most discrepancy tickets become minutes of work.
