# Connector Coverage

**Parent Industry:** [[industries/ai-agent-platforms|AI Agent Platforms]]
**Category:** Low Digitized
**Contested on:** Every serious competitor in this niche is fighting to reach a customer's own systems without a bespoke integration project per deployment — and whoever does that takes the account, because integrations are where deployments stall after the agent already works.

## Profile
**Market Size:** ~$380M US in integration cost and delayed deployments
**Share of Parent Industry:** ~15% of category revenue
**Digital Adoption:** Low — shallow individually, endless collectively
**Target Buyer:** Integration and platform teams on both sides
**Automation Potential:** High — much of the work is generatable

## What Makes This a Distinct Niche
Tool calling is a solved model capability and a connector standard now has real adoption, and deployments still stall on integrations. The reason is that the remaining work is not protocol work: it is a customer's own order system with three decades of accumulated semantics, an internal service with no documentation, a partner API that behaves differently in their tenancy, and a dozen business rules encoded in how a field is used rather than in what it is called. Each integration is individually shallow and collectively endless, and it is the single largest source of time-to-value in the category.

## Current Tools & Gaps
Connector standards with growing adoption, prebuilt integrations for common software, and bespoke integration work per deployment. The gaps: no generation of a connector from an existing interface specification; no capture of the semantics a tool needs beyond its signature, which is where agents actually fail; no testing of a connector against the behaviours an agent will exhibit; no reuse across deployments of the same customer system; and no measurement of which integration gaps cost the most deployment time.
