# Implementation Methodology From Enterprise Software

**Niche:** [[niches/ai-agent-platforms/the-forward-deployed-engineer/profile|The Forward-Deployed Engineer]]
**Industry:** [[industries/ai-agent-platforms|AI Agent Platforms]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Enterprise software spent decades turning implementation from consulting into a repeatable methodology with templates and accelerators, and agent vendors are at the consulting stage.
**Tags:** #worker-facing #workflow-orchestration #automation #evaluation-metrics #data-integration #descriptive-statistics #compliance #quick-win
**Contested on:** Every serious competitor in this niche is fighting to make a deployment work without a person living inside it — and whoever does that takes the market, because the delivery model is currently a headcount line that grows with revenue.

## The Problem
Enterprise resource planning and customer relationship management vendors faced exactly this: an implementation that required expensive consultants on site for months, in a business that needed to scale. They answered it with industry templates, preconfigured processes, structured discovery methodologies, implementation partners and accelerators, over several decades of deliberate work. Agent vendors are at the beginning of that curve and are largely not aware that the curve exists.

## What Already Exists
Industry-specific configuration templates and preconfigured process libraries; structured discovery and requirements methodologies; implementation partner ecosystems with certification; accelerators and rapid deployment programmes; configuration-over-customisation design principles; and post-implementation optimisation practice.

## The Customization Gap
The adaptation is to a system configured by prompts and examples rather than by settings. It requires: (1) templates whose content is prompts, examples, task taxonomies and escalation rules rather than field configurations, which is a different artefact but the same idea and nobody has defined the format; (2) discovery structured around task distribution and exception handling, since what determines an agent deployment is the shape of the work rather than the process diagram the enterprise methodologies elicit; (3) configuration-over-customisation applied to prompts, because a deployment where the engineer rewrote the core prompt is unmaintainable and unupgradable, which is the same lesson enterprise software learned about code modifications; (4) a partner ecosystem, which is how the enterprise vendors escaped the headcount trap and which requires the templates to exist first; and (5) upgrade paths, since a heavily hand-tuned deployment cannot take a platform improvement, and this is the trap that customised enterprise deployments fell into for a generation.

## Target Customer
Vendor delivery leadership, implementation partners, and the enterprise software implementation profession whose methodology transfers with a change of artefact.

## Impact If Solved
Enterprise software escaped this trap with templates, structured discovery and partners, over decades of deliberate work. Configuration-over-customisation applied to prompts is the specific lesson worth taking early, because a hand-rewritten core prompt cannot take a platform upgrade.
