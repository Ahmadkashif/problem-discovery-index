# Routing & Network Optimisation

**Parent Industry:** [[industries/payment-processors|Payment Processors]]
**Category:** Contested Sub-Niche
**Contested on:** Every serious competitor in this niche is fighting to present the transaction in the way most likely to be approved — route, network, token, authentication, data — and whoever does that prevents the declines everybody else is busy retrying.

## Profile
**Market Size:** ~$16B US
**Share of Parent Industry:** ~13% of category revenue
**Digital Adoption:** Medium — routed on cost, not on approval
**Target Buyer:** Payments infrastructure and network relationship leadership
**Automation Potential:** High — routing is decidable, relationships are not

## What Makes This a Distinct Niche
Before any decline happens, several choices have already been made: which acquiring entity presents the transaction, over which network, with which token, through which authentication path, carrying which optional data fields. Each of those materially changes the approval probability, and each is currently decided by cost, by a static rule or by whatever the integration happened to do. This is a routing, infrastructure and network relationship contest — it requires acquiring licences, network agreements and local presence — which makes it a fundamentally different business from modelling retries.

## Current Tools & Gaps
Static routing rules, cost-based least-cost routing, network tokenisation where enabled, authentication configured by rule, and local acquiring in some markets. The gaps: routing optimised for cost rather than for approval; token adoption partial; authentication applied by blunt rule rather than by predicted benefit; optional data fields omitted; and no measurement of which route actually approves better.
