# Facility Booking Systems Turned Toward the Startup

**Niche:** [[niches/contract-research-labs/nanotech-spinouts-shared-facilities/profile|Nanotech Spinouts on Shared Facilities]]
**Industry:** [[industries/contract-research-labs|Contract Research Labs]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Shared-facility software tracks tool bookings, training and billing for the facility; the startup paying for the time gets an invoice and nothing it can use to reproduce its own runs.
**Tags:** #feature-engineering #data-integration #workflow-orchestration #automation #worker-facing
**Contested on:** Every serious competitor serving these firms is fighting to give a nanotech startup production-grade fabrication and characterisation capability without its own cleanroom, and whoever turns rented tool time into reproducible process recipes the startup owns takes the account.

## The Problem
Every run at a shared facility generates a booking, a tool log and, often, characterisation data. The facility's system keeps the first two for its own billing and maintenance; the startup's engineer copies settings into a personal notebook by hand.

## What Already Exists
NEMO, Coral and iLab facility management systems, with booking, qualification tracking, usage billing and tool status.

## The Customization Gap
A startup-facing layer needs: export of each run's tool log and settings to the paying user in a standard format; linkage of bookings to the user's own run records and samples; cross-facility history for users of several facilities; access controls for confidential processes run on shared tools; and usage summaries a startup can attach to grant reports and investor diligence.

## Target Customer
Facility directors seeking more external users, and the startups who would pay a premium for exportable run data.

## Impact If Solved
Facilities compete for startup users on data, not just tool time, and startups stop rebuilding their own run history by hand.
