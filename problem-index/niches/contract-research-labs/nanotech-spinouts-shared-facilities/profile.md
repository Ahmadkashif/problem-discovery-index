# Nanotech Spinouts on Shared Facilities

**Parent Industry:** [[industries/contract-research-labs|Contract Research Labs]]
**Category:** Underserved Audience
**Contested on:** Every serious competitor serving these firms is fighting to give a nanotech startup production-grade fabrication and characterisation capability without its own cleanroom, and whoever turns rented tool time into reproducible process recipes the startup owns takes the account.

## Profile
**Market Size:** ~$120M a year in process documentation, recipe management, characterisation analysis and facility-software tooling and services bought by nanotech spinouts (estimate); NAICS 541713 counted 1,722 establishments in 2023 (County Business Patterns, as reported)
**Share of Parent Industry:** ~6% of contract research labs' tooling and services spend (estimate)
**Digital Adoption:** Low-Medium — tool booking is online; process knowledge lives in run sheets and one engineer's head
**Target Buyer:** Founder-CTO or process engineer at a 3–30-person nanotech firm
**Automation Potential:** Medium — recipe capture, run logging and image analysis are automatable; process development is craft

## What Makes This a Distinct Niche
A nanotech spinout developing a coating, sensor, membrane or device needs lithography, deposition, etching and electron microscopy that cost millions to own. So it rents time in university cleanrooms, NSF-funded shared facilities and DOE user facilities, often several of them, running its process on whatever tool is free. Federal nanotechnology funding is falling — the National Nanotechnology Initiative request dropped from ~$2.2B for FY2025 to $1.45B for FY2026 — while investors expect a reproducible process before they fund a pilot line. The tools these firms use were built for the facilities, not for the firms.

## Current Tools & Gaps
Facility booking and billing systems (NEMO, Coral, iLab); paper and spreadsheet run sheets; instrument software at each facility; shared drives. Gaps: process recipes tied to one facility's tools and not portable; run history scattered across facilities; tacit tuning knowledge held by the one process engineer; characterisation done in each facility's software with inconsistent methods.
