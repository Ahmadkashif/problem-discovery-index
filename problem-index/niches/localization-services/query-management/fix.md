# The Question Asked Thirty Times

**Niche:** [[niches/localization-services/query-management/profile|Query Management]]
**Industry:** [[industries/localization-services|Localization Services]]
**Type:** Fix (Pain Point)
**One-liner:** The answer was given to the German linguist on Tuesday and the Japanese linguist asked the same thing on Thursday.
**Tags:** #quick-win #automation #workflow-orchestration #data-integration #evaluation-metrics #descriptive-statistics #worker-facing #word-embeddings
**Contested on:** Every serious competitor in this niche is fighting to answer a linguist's question once rather than thirty times, and whoever routes and propagates those answers takes the account.

## The Problem
An answer given to one linguist stays with that linguist. It sits in an email thread, or a comment on one language's file, and the other twenty-nine never see it. So the same question is asked repeatedly across a release, the coordinator answers from memory where they can and re-routes where they cannot, and linguists wait for information that already exists somewhere in the project.

## Why It's Still Broken
Answers are delivered privately — a reply sent to the person who asked reaches nobody else, and nothing in the process publishes it, so each language rediscovers the same question independently. Queries arrive through personal channels. Nobody maintains a project answer log. And the coordinator remembering is good enough most of the time.

## What a Fix Looks Like
Publish every answer to everyone on the project. Keep a project query log visible to all linguists with every question and answer, which is the fix and is a shared document rather than a system. Attach answers to the source segment they concern, so a linguist opening that segment sees it. Require linguists to check the log before raising a query, which is a norm rather than a control. Broadcast new answers to the whole project rather than replying privately. Keep the log across releases for the same client, since many questions recur between releases. Mark answers that should become a style guide or glossary entry, which is where the recurring ones belong. Report query volume and the proportion already answered, which shows whether the log is working. Have the coordinator publish rather than relay, which is the same effort with thirty times the effect. Keep it searchable in the linguists' own working language where possible. And review the log after each release for the questions that should have been prevented.

## Who Feels the Pain
Linguists waiting for an answer that already exists; coordinators relaying the same reply repeatedly; source authors asked the same question by several routes; and the release, blocked in several languages at once.

## Impact If Fixed
A reply sent to the person who asked reaches nobody else, so each language rediscovers the same question independently. A shared project query log is the same effort with thirty times the effect.
