# Content Lifecycle From Technical Documentation

**Niche:** [[niches/online-course-platforms/course-maintenance-and-currency/profile|Course Maintenance & Currency]]
**Industry:** [[industries/online-course-platforms|Online Course Platforms]]
**Type:** Buy & Customize (Vertical Adaptation)
**One-liner:** Technical documentation is versioned against the software it describes and reviewed on a cycle, and courses are recorded once and sold forever.
**Tags:** #workflow-orchestration #data-integration #automation #evaluation-metrics #change-point-detection #compliance #confidence-intervals #descriptive-statistics
**Contested on:** Every serious competitor in this niche is fighting to know which courses have gone materially wrong as the tools they teach changed — and whoever detects decay before a learner complains stops selling instruction that no longer matches reality.

## The Problem
Technical documentation solved this: content versioned alongside the software it documents, review cycles with owners, deprecation notices, links between a code change and the documents it affects, and freshness indicators readers can see. It works because documentation that lies about software is worse than no documentation. Course content describing the same software has none of that apparatus and is recorded as video, which is harder to update than text.

## What Already Exists
Versioned documentation tied to releases; review cycles with named owners; deprecation and superseded notices; change-to-document impact linking; and freshness indicators shown to readers.

## The Customization Gap
The adaptation is to video authored by independent creators. It requires: (1) content in a format that cannot be patched line by line, so the update unit is a recorded segment and the economics differ entirely — this is the substantive constraint; (2) authors who are independent instructors with no obligation and no release awareness, unlike a documentation team inside the vendor; (3) no link between the course and the software project, which must be established by inference; (4) a commercial incentive that rewards selling rather than maintaining; and (5) a learner who cannot tell a version mismatch from their own mistake, where a developer reading documentation usually can.

## Target Customer
Catalogue and quality leadership, instructors, learners, and content lifecycle tooling vendors.

## Impact If Solved
Documentation is versioned against software because lying about it is worse than silence, and courses are not. Linking a course to the releases of what it teaches, and making the update unit a segment rather than a course, is the adaptation.
