**Contested on:** Every serious competitor in this niche is fighting to generate reference material from the source of truth rather than maintaining it by hand, and whoever makes that generation reliable takes the account.

## The Problem
Reference material is a large share of a documentation corpus and is derivable from the product. Where it is hand-maintained it drifts immediately. Where it is generated, the generator is frequently a bespoke script that breaks quietly when the source changes shape, producing a reference that is silently incomplete. Either way, writers spend time on material that should require none of it, and the conceptual content that genuinely needs them is what gets squeezed.

## Why Nobody Has Built This
Generation exists for the well-standardised interfaces and not for the rest — configuration options, error codes, event schemas, command-line interfaces. Bespoke generators are written per product and unmaintained. Generated output alone is unhelpful without the prose that explains it, and combining the two is awkward. And nobody monitors whether generation produced what it should.

## What to Build
Generate everything derivable and combine it cleanly with the prose. Generate reference for every interface the product exposes rather than only the standardised ones, which is the core and is where the hand-maintained material lives. Combine generated structure with human-written explanation so the output is useful rather than merely complete, which is the design problem that makes generation acceptable to writers. Detect when generation produces less than the previous run, since silent partial generation is the failure mode nobody notices. Version the reference alongside the product, so readers can see the version they are on. Reconcile generated and hand-written material to find the tables that should have been retired. Enrich the source's own comments and annotations rather than duplicating them in prose, which puts the description where the change happens. Fail the build when generation fails rather than publishing the previous output. Support the interfaces that have no standard — configuration, errors, events — which is where most of the hand maintenance is. Make the generator maintainable rather than bespoke, since that is why the existing ones rot. And measure how much of the reference corpus is generated, which shows where the remaining effort goes.

## Target Customer
Documentation teams and technical content agencies, developer experience and engineering leadership, documentation tooling vendors, and developer platform providers.

## Impact If Built
Reference is a projection of the product's own definitions and much of it is retyped or generated by a script that fails quietly. Generation across every interface, combined with prose, returns the writers to the content that needs them.
