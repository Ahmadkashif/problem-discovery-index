# The Performance Bonus Nobody Can Verify

**Niche:** [[niches/performance-marketing-agencies/the-fee-model/profile|The Fee Model]]
**Industry:** [[industries/performance-marketing-agencies|Performance Marketing Agencies]]
**Type:** Fix (Pain Point)
**One-liner:** The contract pays a bonus for hitting a return target, the return is calculated from platform-reported conversions, and the agency can influence the number it is graded on.
**Tags:** #compliance #evaluation-metrics #hypothesis-testing #confidence-intervals #quick-win #revenue-impact #descriptive-statistics #causal-inference
**Contested on:** Every serious competitor in this niche is fighting to get paid for the finding that a channel is not incremental — and whoever builds a commercial model that rewards that is selling something no percentage-of-spend competitor can match.

## The Problem
A hybrid contract pays a base fee plus a bonus for exceeding a return target. The return is computed from platform-reported conversions, using attribution settings the agency controls, over a window the agency can select, on a metric that includes conversions the platforms would have got anyway. The agency is not doing anything improper; it is optimising toward the number it is measured on, which is what any supplier does. The bonus is being paid on a figure neither party can independently verify and which the graded party can influence, and both sides signed it because it looked like alignment.

## Why It's Still Broken
The bonus metric was chosen because it was available in the platform reporting both parties already look at — availability rather than validity, which is how nearly every bad metric in this cluster was chosen. Clients lack the measurement capability to specify anything better. Nobody wants to raise the problem after signing. And the agency's optimisation toward the metric is invisible and entirely defensible.

## What a Fix Looks Like
Grade on something the graded party cannot move. Define the bonus metric against the client's own revenue system rather than against platform reporting, which is the fix and removes the conflict in a single clause. Fix the attribution settings and windows in the contract, so the measurement cannot be tuned mid-term. Use incremental rather than attributed outcomes where a measurement capability exists, which is the correct metric and is what the build note's model requires. Require an independent calculation, or at minimum a method both parties have specified in writing and can both reproduce. Include a spend efficiency term so reducing waste is rewarded alongside growing outcomes, which is the missing half of every current bonus structure. Set the baseline from a pre-period with an agreed seasonality adjustment, since baseline disputes are what actually end these arrangements. Cap and collar the variance so neither side is exposed to a measurement artefact. Review the metric annually, because platform reporting changes and a fixed metric decays. Disclose any change in measurement configuration as a contractual obligation, which is a simple clause that removes most of the residual risk. And state plainly which conversions are excluded, because the branded and retargeted conversions are where the disagreement always is and naming them up front prevents the argument.

## Who Feels the Pain
Clients paying bonuses on numbers they cannot verify; agencies whose genuine performance is indistinguishable from metric optimisation; and the category, whose attempts at alignment reproduce the measurement problem.

## Impact If Fixed
The bonus metric was chosen for availability rather than validity, and the graded party controls it. Defining it against the client's own revenue system removes the conflict in one clause, and adding a spend efficiency term supplies the missing half.
