# Reporting by Asset Identifier

**Niche:** [[niches/performance-marketing-agencies/creative-operations/profile|Creative Operations]]
**Industry:** [[industries/performance-marketing-agencies|Performance Marketing Agencies]]
**Type:** Fix (Pain Point)
**One-liner:** Performance is reported against a file name, so nobody can say whether the testimonial angle works, only that asset 4471b did well last month.
**Tags:** #descriptive-statistics #evaluation-metrics #data-integration #workflow-orchestration #quick-win #revenue-impact #gradient-boosting #automation
**Contested on:** This niche is not terminal — producing enough assets and knowing which concepts are worth producing are different contests with different winners, and they are stated separately in the sub-niches.

## The Problem
A year of creative testing has produced a spreadsheet of asset identifiers and their performance. Nobody can answer the questions that matter: does the founder-to-camera format work for this brand, do problem-first openings beat product-first ones, does the price-led message outperform the quality-led one. Those are concept-level questions and the data is asset-level, with no attribute recorded beyond a file name and a date. Thousands of pounds of testing produced a list of winners with no transferable finding, and the next campaign starts from scratch for the same reason.

## Why It's Still Broken
Assets are uploaded with names rather than attributes, because the platform asks for a file and not for a description — the data model follows the upload form. Tagging is manual, tedious and skipped under deadline. Nobody owns the taxonomy. And the absence is only felt when someone asks a question the data cannot answer, which is easy to attribute to the question being too hard.

## What a Fix Looks Like
Record what the creative is. Tag every asset with a structured concept taxonomy at production — format, angle, claim type, opening device, talent, message, offer — which is the fix and turns a year of testing into an answerable dataset. Derive tags automatically from the asset itself, since multimodal extraction is now reliable and manual tagging fails under deadline every time — this is what makes the fix survive contact with a busy team. Group assets by concept so performance aggregates across variants, which is where the statistical power is and is why asset-level testing is usually underpowered. Report in concept terms to clients and to the creative team, because that is the language of the decision. Backfill historical assets automatically, which recovers the learning already paid for. Maintain one taxonomy across clients so findings transfer, which is the portfolio asset. Feed concept performance into briefing, so production is directed rather than queued. Separate concept effects from budget and audience effects, since a concept that ran with more spend is not thereby better. Detect concept fatigue rather than asset fatigue, which is the practical decision every account makes weekly and currently makes blind. And report which concepts worked across the portfolio, because that finding is the thing an agency can know and a client cannot.

## Who Feels the Pain
Creative teams whose testing produces no transferable knowledge; clients funding tests that answer nothing; and agencies whose one remaining differentiator is unmeasured.

## Impact If Fixed
The data model follows the upload form, so a year of expensive testing yields a list of file names. Automatic attribute extraction plus concept-level aggregation turns the same spend into answers about angles, formats and claims that transfer to the next campaign.
