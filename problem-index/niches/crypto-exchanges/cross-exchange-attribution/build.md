# Owning the Label Source

**Niche:** [[niches/crypto-exchanges/cross-exchange-attribution/profile|Cross-Exchange Attribution]]
**Industry:** [[industries/crypto-exchanges|Crypto Exchanges]]
**Type:** Build (Greenfield Opportunity)
**One-liner:** Exchanges generate the identity-to-address labels that the attribution industry is built on and buy them back as a feed.
**Tags:** #graph-theory #graph-neural-networks #k-means-clustering #evaluation-metrics #confidence-intervals #compliance #data-integration #gradient-boosting
**Contested on:** Every serious competitor in this niche is fighting to turn the identity-to-address junction that exchanges generate into an asset they own rather than one they rent back from a vendor — and whoever organises that first controls the input the whole industry's compliance runs on.

## The Problem
An address's real-world attribution ultimately traces back to a point where someone with a verified identity touched it — and in practice that point is almost always a regulated exchange's deposit or withdrawal. The exchanges hold millions of these joins. The analytics vendors assemble a picture across many exchanges, add investigative work, and sell the result back. Each exchange sees its own slice, pays for the aggregate, and has never assessed what its own slice is worth or what pooling would produce.

## Why Nobody Has Built This
The vendor relationship predates any exchange's data function, so buying was the default before there was anyone to ask the question — and the arrangement has never been re-examined. Pooling between competitors raises antitrust, privacy and customer-consent questions nobody wanted to lead on. The vendors' cross-exchange aggregation is genuinely valuable and hard to replicate. And no exchange gains much from acting alone.

## What to Build
Organise the asset, starting with what one exchange can do alone. Build attribution from own-junction data first, since a large exchange's own slice is substantial and would immediately reveal how much of the purchased feed it already knows. Measure the overlap with the vendor feed, which is the fastest way to price the relationship honestly and has apparently never been done. Express attributions with confidence and provenance, because that is what makes them poolable and defensible later. Design the pooling structure with the governance answered first — consent, antitrust, privacy, data minimisation — as the legal architecture is the binding constraint and the technical work is comparatively easy. Share abstracted attributions rather than customer data, which is what makes participation possible at all. Use travel rule infrastructure as an existing sanctioned channel, since it already moves counterparty information between exchanges and is underexploited. Contribute and consume symmetrically, so the incentive structure holds. Validate pooled attributions against each participant's own evidence, which gives the pool a quality measure vendor feeds lack. Keep the vendors in the picture where their investigative work is genuinely additive, because replacing them entirely is neither realistic nor necessary. And measure attribution coverage and accuracy against the purchased alternative, which is the number that decides the strategy.

## Target Customer
Exchange data and compliance leadership, industry associations positioned to convene, analytics vendors whose supply chain this is, and regulators interested in attribution quality.

## Impact If Built
Buying was the default before any exchange had a data function to ask the question. Measuring how much of the purchased feed an exchange's own junction data already reproduces is a week of work and has never been done.
