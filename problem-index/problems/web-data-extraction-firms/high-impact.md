# Detecting Semantic Breakage, Not Just Failure

**Industry:** [[web-data-extraction-firms|Web Data Extraction Firms]]
**Type:** High Impact
**One-liner:** A scraper that returns nothing is obvious; a scraper that returns the wrong field with the right shape is invisible, and it feeds corrupted data into a customer's pricing or research pipeline for weeks.
**Tags:** #change-point-detection #hypothesis-testing #confidence-intervals #evaluation-metrics #bert #large-language-models #cnns #descriptive-statistics #revenue-impact

## The Problem
Extraction pipelines break because the web changes. A site is redesigned, a class name is regenerated by a build tool, a field is moved into a component that loads asynchronously, a price is now rendered with a currency symbol in a separate element.

Hard failures are easy. The selector matches nothing, the extraction returns null, monitoring fires. Annoying and quickly fixed.

The expensive failure is different. The selector still matches something, and that something is wrong. A price field that now picks up the strikethrough original rather than the sale price. A product title that captures a category breadcrumb. A review count that is now the answer count from a question section. A date that is the last-modified stamp rather than the publication date.

The extraction succeeds. Types validate. Volume is normal. Nothing alerts. The customer's price monitoring system now believes competitors raised prices, and acts on it. The research dataset now contains a systematically wrong field. Discovery happens when a human eventually looks, which may be weeks.

At the scale these firms operate — thousands of targets, each changing independently — silent semantic breakage is continuous, and nobody knows how much of their delivered data is currently wrong.

## Why It's Unsolved
Correctness requires knowing what the right answer was, and there is no reference. The site is the only source of truth and the whole point is that the extraction disagrees with it in a way nothing detected.

Schema validation cannot help. A wrong price is still a number in a plausible range. A wrong title is still a string. The failure is semantic and passes every structural check.

Change is constant and mostly benign. Sites change continuously without affecting extraction, so a detector based on page differences fires constantly and gets ignored — the same alert fatigue that defeats naive drift detection everywhere.

The economics have discouraged investment. Extraction is priced per page or per record at low margins, and per-record verification is expensive relative to the price. So the industry has optimised throughput and treated correctness as the customer's problem, which is defensible commercially and is why the problem persists.

Model-based extraction has improved resilience meaningfully — a model reading a page for a price is less brittle than a selector — and has not solved verification, because a model can also confidently return the wrong number.

## What a Solution Looks Like
Distributional monitoring per field per source. The distribution of prices from a given site is stable over short periods; a shift in its shape — not just its mean — is evidence of breakage. This catches the strikethrough-price failure immediately, and requires only that field distributions be tracked over time.

Cross-source consistency. The same product appears on several sites, the same company in several directories, the same article across aggregators. Disagreement between sources on entities that should match is a strong signal of extraction error and requires no external truth at all.

Redundant extraction on a sample. Extracting a small fraction of pages by a second method — a different selector, a model-based read, a rendered-versus-raw comparison — and checking agreement gives a direct correctness estimate at bounded cost.

Change classification rather than change detection. A page diff should be classified as affecting the extracted fields or not, which turns a constant stream of benign changes into a small set of relevant ones.

Field-level confidence delivered to customers, so that a low-confidence field is visible rather than silently consumed.

## Impact If Solved
Silent semantic breakage means an unknown fraction of every delivered dataset is currently wrong, and customers are making pricing and research decisions on it. Distributional and cross-source monitoring costs little, requires no ground truth, and converts an invisible failure into an alert — which is the difference between a data service and a data feed.
